# Development checklist

For every change, read this file before editing and check it again before calling the work complete. This applies to people and AI assistants, including changes to code, prompts, settings, and documentation.

Check each item below. If an item does not apply, leave it unchanged and say why when relevant.

- [ ] **Check the impact.** Read [AGENTS.md](AGENTS.md) and identify which parts are affected: MacHelper, extensions, shared APIs, installers, or the marketplace. Keep the same behavior consistent wherever it appears. Remove proven unused code; preserve published interfaces and necessary compatibility paths.
- [ ] **Verify extension independence.** Build or load changed source extensions from detached folders using the installed app or its shipped SDK. Keep feature-specific protocols and prompts with their extension. Shared capability changes also need regression checks for the other installed tools.
- [ ] **Update the explanation.** Update related UI labels/help, [README](README.md), [project design](PROJECT_DESIGN.md), [AI extension guide](AI_EXTENSION_GUIDE.md), detailed `docs/`, SDK examples, and [website](ExtensionMarket-website/README.md) descriptions, instructions, or previews. Removed controls must not remain in current instructions. Change only material affected by the task.
- [ ] **Keep discovery useful.** New/published extensions need their own `discovery.json` with accurate descriptions, capabilities, examples, keywords, limitations, platforms, and translations. After changing it, rebuild and verify the versioned source inventory plus the independent discovery index/manifest; keep website search and its MacHelper service protocol consistent. Preserve the extension-free flow: one explicit Find with AI click validates the need, connects when necessary, and searches. Invalid input must make no local request. An expired/unauthorized session can be renewed once before inference; other AI/provider errors must not be retried automatically. No local-access request is allowed on page load, input edits, language changes, or demos. Keep the local service loopback-only, official-origin-only, and limited to its session/search contract. Searching must never install/run tools or start AI without an explicit action.
- [ ] **Keep languages consistent.** Update every supported language catalog and preserve format parameters. Include visible text inside images, illustrations, screenshots, and charts, plus captions and accessible labels; use localized text or locale-specific assets. Check long translations, small layouts, and right-to-left text. Keep extension labels, preview copy, and artwork with their extension source. Keep shared website labels in the website. Language switches must not call AI or rewrite user prompts, settings values, model IDs, selected text, or real AI answers.
- [ ] **Check release details.** When testing an update over a running MacHelper, verify that the old process exits before the swap and that the new process uses the installed executable. When preparing a release, keep app/tool versions and website download metadata consistent. Check current-version statements too; minimum supported versions and historical examples have different purposes.
- [ ] **Keep downloads consistent.** When packaging changed extension files for release, use a new version and regenerate its full catalog inventory, sizes, and hashes. Preserve previously published files and ZIPs. For new marketplace releases, register the reviewed GitHub commit and keep the website catalogs source-free. If bundled/downloadable documentation or SDK files change, rebuild the affected app/site packages using the documented commands; never edit generated output directly.
- [ ] **Test Apply through the editor’s Paste menu.** **Apply** can use the original editor’s Paste menu command for a clipboard-captured selection without an exact Accessibility range. This path requires the tool’s approved `selection.paste`, a completed result, the original selection gesture, process, window and available focus anchors, and a standard enabled Cut command. After the click, MacHelper stages the result with the original boundary whitespace, checks the window, edit commands and its clipboard ownership again, and requests the app’s standard Paste menu action once. Cut is never invoked. This targets the current selection in the original window. The host cannot distinguish two identical text spans by document offset in this mode. A changed target or missing permission leaves Copy available. The result stays on the clipboard.
- [ ] **Keep selection actions safe.** Test the brief loss of focus when a user clicks Apply. Recheck once only before a write, while the same selection and preview are current. A changed target or attempted write must end the transaction. Enabled selection commands share one toolbar. Keep fixed hit/focus/window/application reads bounded and tied to the original app, with exact origin checks. A system-focus anchor must match the source app PID; an evaluated blocked focus proof stops later, broader fallbacks. Read only the exposing control’s selected range, using attributed text only for the identical range when the plain representation is absent, or exact positive marker proof when no numeric range exists. An explicit caret or invalid numeric range never falls back to markers. Never crawl arbitrary descendants, broaden AX capture to a whole value/document, or silently add Services/OCR capture or screen-reading permission requests. Automatic Copy capture is allowed only once after a recognized selection gesture and failed AX reading, with protected/editable insertion-caret/stale rejection, stable complete memory-only snapshots, bounded polling and guarded restoration that never overwrites a newer clipboard change. Latch double/triple-click and Shift-click intent at mouse-down, retaining selection intent from either mouse-down or mouse-up. Use the current mouse event’s Command flag to recover a missed modifier transition. Commit a fresh read context when the gesture completes so an older read cannot consume its Copy preparation. After Copy, only a timed-out Accessibility source check can trigger bounded revalidation within that gesture. Require fresh source confirmation and never copy again. Double-click, triple-click and Shift-click schedule their first Accessibility read 0.12 seconds after release. Copy becomes eligible 0.35 seconds after release. A double-click also waits until the system double-click interval has elapsed from the second mouse-down so a third click can supersede it. Each completed gesture supersedes older reads. Drag and keyboard reads keep their 0.14-second delay. Polling respects both deadlines. Before any Copy attempt, permit at most three bounded preparation checks for the unchanged gesture, including 60 milliseconds of clipboard quiet and a 0.5-second snapshot budget; never retry a Copy attempt or copy from timer polling. Clipboard-only evidence alone permits reading, not exact-range editing. At tool click, exact-range Apply may recover only from a fresh independent matching AX read with its own positive numeric range/origin and the original context still current. If MacHelper cannot verify either an exact edit target or an eligible Paste menu target, Apply stays disabled. The completed preview offers Copy and explains why. Keep unsupported-app limitations accurate. Pointer-hit reading does not authorize editing. Test mirror selections with different local offsets, as in VS Code. Require matching endpoint markers owned by the focused editable control before using its own positive numeric range and selected text. Mismatched endpoints, stale focus, or text equality alone must keep this path disabled. Command must hide only the idle toolbar and suppress it while held. Latch keyboard selection on key-down and handle both selection-key/Command release orders, publishing only after both are released; Command release alone never rearms. The modifier alone preserves result panels. Tool titles, prompts, and settings belong to extension source. Selection alone makes no AI request. Translation is read-only. Exact-range Apply requires approved `selection.replace`, a completed preview, an explicit click, and target revalidation. Classify the selected control through a bounded Accessibility parent chain: verified web editors use approved paste before any write, verified native controls prefer direct `AXSelectedText`, and a depth/deadline-limited unknown classification permits only approved paste when strict editable-field and full target checks pass. Missing/cyclic/protected ancestry stays blocked with Copy; unknown classification never permits a direct setter. No browser/app allowlist chooses this route. Never retry a direct write by pasting. Optional separately reviewed `selection.paste` also requires `selection.read`/`selection.replace`: the separate Apply transaction writes only the result and own clipboard stamp, never reads/snapshots/restores previous contents, revalidate source PID/focus/AX identity/numeric range/text/editability plus own clipboard count/stamp, then send only fixed Command-V down/up to that PID. No activation, range forcing, arbitrary keys, Enter/Send, whole-field value rewrite, or unselected-text reconstruction. Keep Copy, honest requested-versus-confirmed status, and no automatic retries. Test disposable partial/full/read-only/changed selections without sending messages.
- [ ] **Verify the change.** Run the relevant existing checks from the [README](README.md) or website guide. Check local documentation links. Verify changed UI in the installed app when installation is part of the task. A documentation-only change does not require unrelated tests.
- [ ] **Test read-only pointer Copy.** Verify noneditable static text with empty range placeholders inside the focused window can use direct Edit > Copy once. Reject editable carets, protected or unresolved ancestry, disabled or nonstandard Copy, and keyboard-only use of this path. Keep its result preview-only and verify clipboard restoration with disposable data.

- [ ] **Test Electron compatibility.** Leave the preference off by default. With it enabled, test an ordinary readable selection and an unreadable selection in a fresh VS Code window. Only the unreadable selection may trigger the bounded Accessibility request. Verify that the same window gets at most one initial request and one settled refresh, a second window can recover independently, and switching windows cancels outstanding work for the old selection. Verify that polling and toggling the preference cannot initiate the request. Reselect after activation if the first selection was missed. Preserve VS Code settings, VoiceOver, OS permissions, and the usual Apply checks. See the [host contract](docs/Source-Extensions.md#shared-toolbar-and-guarded-replacement-machelper-66).
- [ ] **Protect private files.** Keep `AI_DEPLOYMENT.md`, credentials, and user data out of Git, logs, and downloads. Follow the existing project rules in `AGENTS.md`.
- [ ] **Report the actual result.** State what changed and what was checked. Distinguish source changes, local builds, installed apps, GitHub pushes, and live website deployments. Building or pushing does not deploy the website; install or publish only within the user's authorized scope.

Do not mark a change complete while a related update or required check is still missing. Fix it, or clearly report the remaining blocker.
