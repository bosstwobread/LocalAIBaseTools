# Development checklist

For every change, read this file before editing and check it again before calling the work complete. This applies to people and AI assistants, including changes to code, prompts, settings, and documentation.

Check each item below. If an item does not apply, leave it unchanged and say why when relevant.

- [ ] **Check the impact.** Read [AGENTS.md](AGENTS.md) and identify which parts are affected: MacHelper, extensions, shared APIs, installers, or the marketplace. Keep the same behavior consistent wherever it appears. Remove proven unused code; preserve published interfaces and necessary compatibility paths.
- [ ] **Update the explanation.** Update related UI labels/help, [README](README.md), [project design](PROJECT_DESIGN.md), [AI extension guide](AI_EXTENSION_GUIDE.md), detailed `docs/`, SDK examples, and [website](ExtensionMarket-website/README.md) descriptions, instructions, or previews. Removed controls must not remain in current instructions. Change only material affected by the task.
- [ ] **Keep discovery useful.** New/published extensions need their own `discovery.json` with accurate descriptions, capabilities, examples, keywords, limitations, platforms, and translations. After changing it, rebuild and verify the versioned source inventory plus the independent discovery index/manifest; keep website search and its MacHelper service protocol consistent. Preserve the extension-free flow: one explicit Find with AI click validates the need, connects when necessary, and searches. Invalid input must make no local request. An expired/unauthorized session can be renewed once before inference; other AI/provider errors must not be retried automatically. No local-access request is allowed on page load, input edits, language changes, or demos. Keep the local service loopback-only, official-origin-only, and limited to its session/search contract. Searching must never install/run tools or start AI without an explicit action.
- [ ] **Keep languages consistent.** Update every supported language catalog and preserve format parameters. Include visible text inside images, illustrations, screenshots, and charts, plus captions and accessible labels; use localized text or locale-specific assets. Check long translations, small layouts, and right-to-left text. Extension labels/assets belong in extension source; website artwork translations belong in the website. Language switches must not call AI or rewrite user prompts, settings values, model IDs, selected text, or real AI answers.
- [ ] **Check release details.** When preparing a release, keep app/tool versions and website download metadata consistent. Check current-version statements too; minimum supported versions and historical examples have different purposes.
- [ ] **Keep downloads consistent.** When packaging changed extension files for release, use a new version and regenerate its full catalog inventory, sizes, and hashes. Preserve previously published files and ZIPs. If bundled/downloadable documentation or SDK files change, rebuild the affected app/site packages using the documented commands; never edit generated output directly.
- [ ] **Keep selection actions safe.** Enabled selection commands share one toolbar. Keep fixed hit/focus/window/application reads bounded and tied to the original app, with exact origin checks. A system-focus anchor must match the source app PID; an evaluated blocked focus proof stops later, broader fallbacks. Read only the exposing control’s selected range, using attributed text only for the identical range when the plain representation is absent, or exact positive marker proof when no numeric range exists. An explicit caret or invalid numeric range never falls back to markers. Never simulate Copy, crawl arbitrary descendants, broaden capture to a whole value/document, or silently add Services/OCR capture or screen-reading permission requests. Keep unsupported-app limitations accurate. Pointer-hit reading does not authorize editing. Command must hide only the idle toolbar, suppress it while held, and not reopen it on release alone; the modifier alone preserves result panels. Tool titles, prompts, and settings belong to extension source. Selection alone makes no AI request. Translation is read-only; replacement requires approved `selection.replace`, a completed preview, explicit Apply, and exact target revalidation. Classify the selected control through a bounded Accessibility parent chain: verified web editors use approved paste before any write, verified native controls prefer direct `AXSelectedText`, and a depth/deadline-limited unknown classification permits only approved paste when strict editable-field and full target checks pass. Missing/cyclic/protected ancestry stays blocked with Copy; unknown classification never permits a direct setter. No browser/app allowlist chooses this route. Never retry a direct write by pasting. Optional separately reviewed `selection.paste` also requires `selection.read`/`selection.replace`: write only the result and own clipboard stamp, never read/snapshot/restore previous contents, revalidate source PID/focus/AX identity/numeric range/text/editability plus own clipboard count/stamp, then send only fixed Command-V down/up to that PID. No activation, range forcing, arbitrary keys, Enter/Send, whole-field value rewrite, or unselected-text reconstruction. Keep Copy, honest requested-versus-confirmed status, and no automatic retries. Test disposable partial/full/read-only/changed selections without sending messages.
- [ ] **Verify the change.** Run the relevant existing checks from the [README](README.md) or website guide. Check local documentation links. Verify changed UI in the installed app when installation is part of the task. A documentation-only change does not require unrelated tests.

- [ ] **Keep compatibility opt-in.** Electron compatibility stays off by default. Its checkbox only saves a Boolean. Disclose full Accessibility requests, possible Screen Reader Optimized behavior changes (including VS Code folding/minimap), and app restarts after opting out. Only a recognized selection gesture may begin one bounded advertised/settable `AXManualAccessibility = true` handshake per process identity: an initial request and at most one follow-up true request no earlier than 2.2 seconds later, with advertised/settable support, process/launch, selection context, trust, and opt-in checked again. Only a new selection gesture may resume a stale pending second phase at its original deadline, without repeating the initial request; polling never resumes it; never use `AXEnhancedUserInterface`, false writes, VoiceOver toggles, or OS permission changes. Preserve context checks and Copy fallback after the delayed read.
- [ ] **Protect private files.** Keep `AI_DEPLOYMENT.md`, credentials, and user data out of Git, logs, and downloads. Follow the existing project rules in `AGENTS.md`.
- [ ] **Report the actual result.** State what changed and what was checked. Distinguish source changes, local builds, installed apps, GitHub pushes, and live website deployments. Building or pushing does not deploy the website; install or publish only within the user's authorized scope.

Do not mark a change complete while a related update or required check is still missing. Fix it, or clearly report the remaining blocker.
